# 0003: 一次请求 + 首行标记的答案协议

## 状态

已接受（Phase 1，V7）；多选已取消，仅保留单选题/判断题。

## 背景

现有 `AIClient.ask` 只返回一段文本，`Worker` 把它当代码缓存和输出。要支持单选题/判断题，模型必须同时告诉工具“这是什么题型”和“答案是什么”。

候选方案：

- **两次请求**：先分类，再按类型作答。更稳，但每题多一次网络往返，延迟和失败面翻倍。
- **JSON 输出**：结构清晰，但部分 OpenAI 兼容端点不支持 `response_format`；代码正文还要转义，容易污染现有代码路径。
- **本地正则硬判**：快，但选项没有字母、题干含代码、混合题时容易误判。
- **一次请求 + 首行标记**：模型在正文前输出一行类型/答案；代码题不输出标记，保持现有行为。

## 决定

采用一次请求 + 首行标记：

- `[[CHOICE:A]]`：单选题，只接受恰好一个 A–D 字母。
- `[[BOOL:T]]` / `[[BOOL:F]]`：判断题。
- `[[UNSUPPORTED]]`：多选题、5 个以上选项、E/F 选项等不支持的题目；工具软失败。
- 代码题不输出标记；工具把整段响应当代码。
- 协议指令由代码追加到用户 `system_prompt` 之后，不要求用户修改 `config.json`。
- 解析器只接受 A–D；容错大小写、全角、逗号/顿号/空格分隔。
- `[[MULTI:...]]` 或多字母 payload 一律视为多选，返回软失败；不把多选降级成单选。
- 题目明显像选择题/判断题、但标记缺失或非法：软失败（清空答案、保持 READY、不打字、可重试）。
- 题目像代码题：保持现有行为，整段响应作为代码。
- 可选容忍并剥离行首 `[[CODE]]`，避免模型多输出标记时把标记打进编辑器。

## 后果

- 模型必须遵守首行格式；不遵守时用户会看到绿色就绪点而不是答案，需要再按一次热键。
- 多选题没有答案交付路径；这是 Phase 1 的明确非目标。
- 解析器需要单元测试覆盖标记、分隔符、全角、非法/越界答案和代码回退。
- 用户的自定义 `system_prompt` 不被修改；协议指令在请求时追加。
- 没有新增配置字段，不需要迁移 `config.json`。
- JSON 输出和两次请求方案被拒绝，原因是延迟、兼容性和改动面。
